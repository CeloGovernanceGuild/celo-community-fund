# Celo Community Fund Status

## Overview 

This repository is to keep a canonical history of the Celo Community Fund status and initiatives that have utilized the fund. Previously, the data was segregated and hard to decipher current initiatives that were in draft proposal phase, initiatives that had spend approval and the remaining funds available to them. It was also difficult to have a high level overview of the total funds.

## What is the fund?

The Community Fund provides for general upkeep of the Celo platform. CELO holders decide how to allocate these funds through governance proposals. Funds might be used to pay bounties for bugs or vulnerabilities, security audits, or grants for protocol development.

The Community Fund receives assets from three sources:

- The Community Fund obtains a desired epoch reward defined as a fraction of the total desired epoch rewards (governable, initially planned to be 25%). This amount is subject to adjustment up or down in the event of under- or over-spending against the epoch rewards target schedule. The Community Fund epoch rewards may be redirected to bolster the Reserve.

- The Community Fund is the default destination for slashed assets.
- The Community Fund also receives the 'base' portion of transaction fees.


## Initiatives

The data in `src/data` is generated from an on-chain audit of every executed governance proposal:
see [docs/audit.md](docs/audit.md) for the full ledger, every execution transaction and the findings,
and [scripts/audit](scripts/audit) to re-run it. A scheduled workflow re-runs the audit every day and
opens a pull request into `dev` when something changed.

Nothing is rounded: every amount is kept in wei and displayed with all its decimals. For each spender
the ledger shows what governance approved, what was already claimed and what is still allowed, so an
allowance with 1 wei left is visible as open.

## Webpage

[celocommunityfund.xyz](https://www.celocommunityfund.xyz) reads the Community Fund
([governance contract](https://celoscan.io/address/0xD533Ca259b330c7A88f74E000a3FaEa2d63B7972)) live from the chain.
The design follows the celo.org brand: yellow page, black ink, serif display type.

### Pages

- **Overview**: balance, available, committed and claimed CELO; what the balance is made of; open
  allowances and the latest grants.
- **Ledger**: every grant per recipient and token with approved, claimed and remaining amounts.
  Searchable and filterable. Each line opens into the proposals that funded it, with the execution
  transaction.
- **Balances**: Community Fund and Reserve holdings with USD values from Chainlink, and the fund's
  commitments per token.
- **Proposals**: drafted and in-progress CGPs, their on-chain stage and funding requests.
- **About**: how to read the numbers and where the data comes from.

Amounts are shown in whole units; the exact value is in the hover title and in `docs/audit.md`.

## Development

Requires Node.js 22 (see `.nvmrc`).

```sh
npm ci
npm run dev      # start the dev server
npm test         # run unit tests
npm run build    # production build into ./build
```

### Docker

The `Dockerfile` builds the site and serves it with Caddy on port 80 (`deploy/Caddyfile`). Put it behind
a reverse proxy that terminates TLS:

```sh
docker build -t celo-community-fund .
docker run -d --name celo-community-fund -p 8080:80 celo-community-fund
```

### Project structure

```
src/
  data/
    ledger.js           every grant, generated by scripts/audit (exact wei)
    proposals.js        pending CGPs and their on-chain stage, generated by scripts/audit
    drafts.js           manual drafts without a CGP (the only data edited by hand)
    data.js             addresses, price feeds, colors, regular inflow
  lib/
    celo.js             on-chain reads (viem): balances, allowances, Reserve, Chainlink prices
    fund.js             pure BigInt derivation of the ledger, totals and charts (tested)
    format.js           exact wei formatting (tested)
  pages/                Overview, Ledger, Balances, Proposals, About
  components/           Amount, charts (segmented bar, claim progress)
  App.jsx               layout and navigation
  index.css, App.css    design tokens and styles
scripts/
  status.js             CLI version of the dashboard (npm run status)
  audit/                governance audit that generates src/data and docs/audit.md
docs/audit.md           audit report
Dockerfile, deploy/     container image for self-hosting
.github/workflows/      CI, branch flow check, daily audit
```

### Branches and releases

`feature branch -> dev -> main`. `dev` and `main` are protected: changes go
through pull requests with passing CI, and only `dev` can be merged into
`main`. See [CONTRIBUTING.md](CONTRIBUTING.md).

## CLI

```
-------Community Fund-------

CICLOPS: <remaining allowance>
...
-------Drafts-------
--------------------
Regular inflow: ~30 CELO per day
Funds Available (after allowances and drafts): <amount>
```
